## 📚 1. Append vs Merge — First Understand the Difference

| Operation | Purpose | Typical Use |
|---|---|---|
| **Append** | Add rows from similar tables | Combine monthly, regional, or plant files |
| **Merge** | Add columns using matching keys | Bring lookup or reference information into a table |

### 💡 Simple Rule

- 💡 **Append = More Rows**
- 💡 **Merge = More Columns**

## 📚 5. Common Join Types

| Join Type | Result |
|---|---|
| **Left Outer** | All rows from first table + matches from second |
| **Right Outer** | All rows from second table + matches from first |
| **Full Outer** | All rows from both tables |
| **Inner** | Only matching rows |
| **Left Anti** | Rows only in the first table |
| **Right Anti** | Rows only in the second table |

### 💡 Practical Guidance

- 💡 **Left Outer** is common for adding lookup information.
- 💡 **Inner** is useful when only matched records are required.
- 💡 **Anti joins** are excellent for finding unmatched or missing records.

⚠️ Match columns should have compatible data types and comparable values.

**Pivot** converts values from rows into columns.

Use when categories need to become separate columns.

## 📚 11. Introduction to M Language

Power Query automatically generates **M code** for most UI transformations.

### Core Structure

```powerquery
let
    Step1 = ...,
    Step2 = ...,
    Step3 = ...
in
    Step3
```

### Key Elements

- 📚 `let` — starts the sequence of expressions.
- 📚 Step names — store intermediate results.
- 📚 Commas — separate steps.
- 📚 `in` — returns the final step.
- 📚 `each` — commonly represents a row-level function.
- 📚 `#""` — allows step names containing spaces.

---

## 💻 12. M Language Guided Example

Open:

- 🗂️ `Classwork Files/ClassWork-5 (M Language).pbix`

Also demonstrate a small independent query in **Advanced Editor**:

```powerquery
let
    Source = #table(
        {"Product", "Qty"},
        {
            {"Product A", 10},
            {"Product B", 20},
            {"Product C", 0}
        }
    ),
    #"Changed Type" =
        Table.TransformColumnTypes(
            Source,
            {{"Product", type text}, {"Qty", Int64.Type}}
        ),
    #"Filtered Rows" =
        Table.SelectRows(
            #"Changed Type",
            each [Qty] > 0
        )
in
    #"Filtered Rows"
```

### Explain Only These Points

- 🧮 `#table()` creates a small table.
- 🧮 `Table.TransformColumnTypes()` changes data types.
- 🧮 `Table.SelectRows()` filters rows.
- 🧮 `each [Qty] > 0` represents the filter condition.
- 🧮 The `in` statement returns the final step.

## 💡 13. UI First, M When Needed

### Recommended Learner Approach

- 💡 Use the Power Query UI for standard transformations.

- 💡 Modify M when the UI is repetitive or insufficient.

⚠️ A single M syntax error can prevent the query from evaluating.

## 💡 Trainer Guidelines

- 💡 Reinforce **Append = rows** and **Merge = columns**.
- 💡 Use Left Outer first before demonstrating other join types.
- 💡 Use Anti joins to explain unmatched-record checks.
- 💡 Emphasize that **Group By changes the grain** of the result.
- 💡 Teach Unpivot as a data-modeling preparation technique, not only a button.
- 💡 Keep M introductory and readable; avoid advanced custom functions here.
- 💡 Demonstrate generated M before asking learners to edit it.
- ⚠️ Confirm matching key columns have compatible data types before Merge.
